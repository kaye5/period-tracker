# Period Tracker

A single-user menstrual cycle tracker. It records periods and symptoms, and turns them
into **honest** statistics, predictions, and personal insights — predictions are shown
as date **ranges** with a plain-language confidence, never a single certain date, and
insights report what you recorded without claiming a cause or a diagnosis.

The engine's algorithms and constants come from a cited literature review in
[`docs/research/`](docs/research). The product rules and acceptance criteria live in
[`docs/SPEC.md`](docs/SPEC.md); design decisions and their trade-offs in
[`docs/DECISIONS.md`](docs/DECISIONS.md).

## ⚠️ Read this first: where your data lives

This build stores your data in a **SQL database** (MySQL, or TiDB — both speak the MySQL
wire protocol). It connects to whatever `DATABASE_URL` points at, and **you choose where
that database runs**:

- Point it at a database **on this machine** (e.g. the local Docker MySQL below) and your
  data stays on the machine.
- Point it at a **hosted service** (TiDB Cloud, a hosted MySQL provider) and the periods,
  symptoms, and notes you record **leave this device** and are stored on that provider's
  servers.

Either way, this app adds no protection of its own, has no app lock, and keeps the database
credentials in plain text in `.env.local` on your machine. For a hosted database, your
data's protection depends on that provider and your account with them (use a strong
password, enable 2FA where offered, restrict network access).

Read [`docs/PRIVACY.md`](docs/PRIVACY.md) in full before recording anything real. It is
plain, not marketing.

## Stack

- Next.js 16 (App Router), React 19, TypeScript (strict)
- Tailwind v4, system-font stack (no remote fonts, no third-party scripts)
- A MySQL-wire database (MySQL / TiDB) via **Drizzle ORM** on the **mysql2** driver;
  migrations generated by **drizzle-kit**; `zod` for boundary validation (DEC-011)
- Vitest for tests; charts are hand-rolled inline SVG; the clinician report prints via
  the browser's "Save as PDF" (no charting or PDF dependency)

## Setup

1. Install dependencies:

   ```bash
   pnpm install
   ```

2. Copy the env template and fill in your values:

   ```bash
   cp .env.example .env.local
   ```

   `.env.local` needs one variable — `DATABASE_URL` (a
   `mysql://user:password@host:3306/period_tracker` string) — plus an optional
   `DATABASE_SSL=true` for hosted services that require TLS (TiDB Cloud does; its default
   port is usually 4000). It is gitignored; never commit it.

3. Start a database. For local development, bring up the Docker MySQL (already matches the
   local `DATABASE_URL` in `.env.example`):

   ```bash
   pnpm db:up       # starts MySQL 8 on 127.0.0.1:3306, waits on its healthcheck
   ```

   To use a hosted MySQL/TiDB instead, skip this and just point `DATABASE_URL` at it.

4. Apply the schema (migrations are generated by `drizzle-kit` into `./drizzle`):

   ```bash
   pnpm db:generate   # only when the schema in lib/db/schema.ts changed
   pnpm db:migrate    # applies pending migrations to DATABASE_URL
   ```

5. (Optional) Seed a realistic 14-cycle sample dataset to explore the app:

   ```bash
   pnpm db:seed
   ```

6. Run the app:

   ```bash
   pnpm dev
   ```

   Open [http://localhost:3000](http://localhost:3000). With no data yet, the home route
   sends you to onboarding. (`pnpm db:reset` tears the local database down and re-runs
   migrate + seed from scratch.)

## Checks

```bash
pnpm typecheck        # tsc --noEmit
pnpm test             # vitest run — unit + mapping tests, no database needed
pnpm lint             # eslint
pnpm test:integration # live repo round-trip tests against a LOCAL throwaway DB
```

`pnpm test` needs no database; the live repo round-trip tests skip unless a database is
configured. `pnpm test:integration` runs those against a dedicated **`period_tracker_test`**
database on the local Docker MySQL (`pnpm db:up` first). It is **destructive** — it wipes
every table — so a guard refuses to run it against any database whose name does not end in
`_test`. It will never touch your real `DATABASE_URL` data, local or on TiDB Cloud.

The test suite covers the date arithmetic, statistical primitives, the cycle/prediction/
insight/health engines (including the research invariants), the relational repo mappings,
and the UI helper logic.

## What this app does not do

It is a personal tracking and education tool — **not** a diagnostic service, an
ovulation-confirmation device, or a contraceptive method. It does not detect or diagnose
any condition, and it should not be relied on to achieve or avoid pregnancy.
