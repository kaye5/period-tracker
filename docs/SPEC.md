### 0.1 The privacy delta — state it, do not paper over it

The source PRD asks for local-only storage, encryption at rest, and an app lock. This build has
MongoDB without encryption and without a lock. That is a deliberate, user-made trade-off, and the
product must not claim otherwise.

Therefore:

- `docs/PRIVACY.md` must state plainly what is and is not protected in this build.
- The settings screen must show the same statement, not a reassuring paraphrase.
- No string anywhere may claim the data is encrypted, private-by-design, or secure.
- Mongo binds to `127.0.0.1` only, with auth enabled and credentials in `.env.local` (gitignored).
- No analytics. No telemetry. No third-party script, font, or image loaded from a remote origin.
  A CI test asserts the absence of outbound `fetch`/`XMLHttpRequest` to non-relative URLs in `app/`
  and `components/`.

## 1. Non-negotiable engineering rules

**R1 — Civil dates only.** Every date the user perceives (period start, log date, predicted range) is a
*civil date*, not an instant. Store as `"YYYY-MM-DD"` strings. Never store a `Date`, never store an ISO
instant, never call `new Date()` for date arithmetic outside `lib/date/civil.ts`. This is the single
largest source of bugs in period apps: a user in UTC+2 logging at 00:30 must not have their period start
recorded as the previous day. `lib/date/civil.ts` is the only file permitted to construct `Date` objects,
and it does so pinned to UTC noon.

**R2 — Recorded vs derived.** `dayLogs` is the sole source of user-recorded truth. Bleeding episodes,
cycles, statistics, predictions, insights and health messages are **derived by pure functions** from
`dayLogs` + `profile`. Derived data may be cached but must be recomputable from scratch at any time.
Editing any historical day triggers full recomputation (PRD §17). Never mutate recorded data to make a
derivation convenient.

**R3 — The engine is pure.** Everything under `lib/engine/` and `lib/date/` and `lib/stat/` must be
free of I/O, `Date.now()`, randomness, environment access, and React. Functions take data in and return
data out. "Today" is always an explicit `CivilDate` parameter. This is what makes the engine testable
and what makes the tests deterministic.

**R4 — Cite your constants.** Every magic number in `lib/engine/constants.ts` carries a comment naming
the source (`S1`…`S22` from the research docs, or `[choice]`). A constant with no provenance is a bug.

**R5 — Never assume 28 days, never assume a 14-day luteal phase.** Only 13% of cycles are 28 days; only
~24% of ovulations fall on day 14–15. Grep-able CI test forbids the literals `28` and `14` appearing as
cycle/luteal defaults outside the cited constants file.

**R6 — Spotting never opens a cycle.** Cycle length is first-bleed-day to first-bleed-day, menstrual
bleeding only. A spotting-only day cannot start a cycle, ever.

**R7 — Never silently discard or split user data.** Anomalies produce *annotations* and *user prompts*,
never mutations. An excluded cycle stays visible in history, marked, with the reason.

**R8 — Uncertainty is a first-class output.** No function in the prediction path may return a bare date.
Return `{ center, low, high, confidence, basis }`. A caller that wants a single date is a caller with a
bug.

**R9 — Copy lives in a catalogue, not in components.** All user-facing strings that make a claim about
the user's body live in `lib/copy/`. A lint test runs over the catalogue and fails on banned words
(§4.4). Strings inline in JSX bypass the lint and are therefore forbidden for any such claim.

**R10 — Tests are part of the deliverable.** A file without tests is not done. Target: every exported
function in `lib/engine/`, `lib/stat/`, `lib/date/` has tests including the edge cases named in the
research docs. The invariants listed in `02-symptom-insights.md` §E.5 are encoded as executable tests.

// ---------- dates ----------
export type CivilDate = string & { readonly __civilDate: unique symbol }; // "YYYY-MM-DD"

// ---------- recorded data ----------
export type BleedingKind = 'none' | 'spotting' | 'menstrual';
export type FlowLevel    = 'spotting' | 'light' | 'medium' | 'heavy' | 'very_heavy';
export type BleedingContext = 'period' | 'intermenstrual' | 'postcoital' | 'unexpected';
export type PainSeverity = 'none' | 'mild' | 'moderate' | 'severe';
export type ClotSize     = 'none' | 'small' | 'ge_2_5cm';   // "quarter or larger" = ge_2_5cm

export interface DayLog {
  date: CivilDate;                       // primary key
  bleeding: BleedingKind;
  flow?: FlowLevel;
  bleedingContext?: BleedingContext;
  periodBoundary?: 'start' | 'end';      // explicit user assertion, not inferred
  clots?: ClotSize;
  productChanges?: number;               // count in the day
  fastestProductChangeHours?: 0.5 | 1 | 2 | 4 | 8; // shortest interval between changes
  doubleProtection?: boolean;
  nightChange?: boolean;
  leakThrough?: boolean;
  pain: { severity: PainSeverity; sites?: PainSite[]; interferedWith?: Interference[];
          painkillerDidNotHelp?: boolean };
  symptoms: SymptomId[];                 // presence-only; absence is *unknown* unless nothingToReport
  nothingToReport?: boolean;             // one-tap: converts unknown -> true negative
  mood?: MoodId[];
  notes?: string;
  fertility?: FertilityObservations;     // only present when settings.fertilityEnabled
  loggedAt: CivilDate;                   // the day the entry was made (back-entry detection, S17)
}

// ---------- profile ----------
export interface Profile {
  birthYear?: number;
  menarcheYear?: number;                 // -> gynecologic age
  reportedTypicalCycleLength?: number;   // onboarding, used only until N>=1
  reportedTypicalPeriodDays?: number;
  reportedRegularity?: 'consistent' | 'variable' | 'unknown';
  state: LifeStageState;
  settings: Settings;
}

export interface LifeStageState {
  pregnant: boolean;
  deliveryDate?: CivilDate;              // -> daysSinceDelivery
  breastfeeding: boolean;
  hormonalMethod?: { kind: HormonalMethodKind; startedOn: CivilDate };
  copperIudInsertedOn?: CivilDate;
  stoppedHormonalOn?: CivilDate;
  perimenopauseSelfDeclared: boolean;
  menopauseSelfDeclared: boolean;
  knownIrregular: boolean;
  preferNotToSay: boolean;
}

export interface Settings {
  fertilityEnabled: boolean;             // DEFAULT false
  tierCSymptomsEnabled: boolean;         // DEFAULT false (sleep/exercise/focus/libido)
  healthAwarenessEnabled: boolean;       // DEFAULT true
  notifications: { periodReminder: boolean; fertileReminder: boolean; symptomReminder: boolean;
                   medicationReminder: boolean; loggingReminder: boolean; healthAwareness: boolean;
                   privateWording: boolean /* DEFAULT true */ };
  locale: 'en-US' | 'en-GB';             // gates URG-02 wording
}

// ---------- derived ----------
export type CycleStatus = 'ok' | 'gap_unknown' | 'skip_suspected' | 'excluded_by_user' | 'in_progress';

export interface BleedingEpisode {
  startDate: CivilDate;
  endDate: CivilDate | null;             // null = ongoing or never ended
  menstrualDays: CivilDate[];
  spottingDays: CivilDate[];
  durationDays: number | null;
  endInferred: boolean;                  // true when no explicit 'end' boundary was logged
}

export interface Cycle {
  index: number;                         // 0 = most recent completed
  startDate: CivilDate;
  nextStartDate: CivilDate | null;       // null for in-progress
  lengthDays: number | null;
  status: CycleStatus;
  statusReason?: string;                 // human-readable, shown in history
  impliedSplitCount?: number;            // k* when skip_suspected
  weight: number;                        // 1.0 normally, 0.5 for user-confirmed inferred splits
  episode: BleedingEpisode;
}

export interface PredictionResult {
  kind: 'none' | 'population_estimate' | 'personal';
  center: CivilDate | null;
  low: CivilDate | null;
  high: CivilDate | null;
  predictedLengthDays: number | null;
  confidence: 'not_enough_information' | 'early_estimate' | 'limited' | 'more_consistent';
  confidenceReason: string;              // from lib/copy, always populated
  basis: { usableCycles: number; windowCycles: number; effectiveN: number;
           sigma: number; halfWidthDays: number; calibrationFactor: number };
  suppressed?: { reason: 'pregnant' | 'postpartum' | 'insufficient_data' | 'hormonal_method' };
}

export interface FertilityEstimate {           // only computed when settings.fertilityEnabled
  ovulationLow: CivilDate; ovulationHigh: CivilDate;
  fertileLow: CivilDate;   fertileHigh: CivilDate;
  confidenceNote: string;
  disclaimer: string;                          // rendered adjacent, never behind a link
}

export interface Insight {
  id: string;
  headline: string;
  body: string;
  detail: string;                               // the supporting counts
  supportingCycles: number;
  supportingDates: CivilDate[];                 // "view the records behind this"
  replicatedLastCycle: boolean;
  kind: 'cycle' | 'duration' | 'symptom' | 'flow' | 'performance';
}

export interface HealthMessage {

  severity: 'informational' | 'discuss_with_clinician' | 'seek_urgent_care';
  message: string;
  sourceName: string; sourceUrl: string; sourceThreshold: string; // "Why am I seeing this?"
  dismissible: boolean;                          // false for URG-01, PMB-01

## 4. Cross-cutting requirements

### 4.1 Recomputation
`lib/engine/index.ts` exposes one entry point:
```ts
export function computeEverything(input: {
  dayLogs: DayLog[]; profile: Profile; today: CivilDate;
  decisions: UserDecisions; calibration: CalibrationState;
}): EngineOutput   // { episodes, cycles, prediction, fertility?, stats, insights, healthMessages, performance }
```
Every screen reads from one `EngineOutput`. No screen recomputes anything locally. Any write to
`dayLogs` or `profile` invalidates and recomputes. This is how PRD §17's "editing a historical period
recalculates later cycles" is satisfied structurally rather than by remembering to.

### 4.2 Recorded vs predicted must be visually distinguishable
Enforced in `components/calendar/`: recorded days use solid fills; predicted days use a dashed outline
with no fill, **plus** a distinct icon and a text label in the day's accessible name. Colour alone is
never the carrier. A test asserts every calendar day cell exposes a non-colour indicator.

### 4.3 Confidence vocabulary
Only these four values ever reach the UI: *Not enough information* (N<3), *Early estimate* (no completed
cycle, using the user's reported typical length), *Limited* (recent cycles vary considerably),
*More consistent* (several recent cycles similar). Each is always accompanied by its reason string
naming the actual numbers. Never a percentage. Never "accuracy".

### 4.4 Banned-word lint (`lib/copy/lint.test.ts`)
Runs over every exported string in `lib/copy/`. Fails on, case-insensitively:
`abnormal`, `pathological`, `disorder`, `diagnos`, `screening`, `detect`, `hormone`, `hormonal imbalance`,
`imbalance`, `PMS`, `PMDD`, `PCOS`, `endometriosis`, `causes`, `because of your`, `linked to`,
`significant`, `p =`, `safe day`, `guaranteed`, `cannot become pregnant`, `you are ovulating`,
`accuracy`, `% accurate`, `medical-grade`, `clinically accurate`.
Exceptions (a small allowlist) are permitted only for: attributed quotations that name their source, the
word "hormonal" inside `hormonal method`/`hormonal contraception` as a neutral state label, and the
disclaimer text. Every exception is listed explicitly in the test file with a justification comment.

### 4.5 Accessibility
Keyboard-operable calendar (arrow keys move the focused day, Enter opens the log). Every interactive
target ≥44×44px. Contrast ≥4.5:1 in both light and dark. No information carried by colour alone.

### 4.6 Definition of done, per agent
1. `pnpm exec tsc --noEmit` clean for your files.
2. `pnpm exec vitest run` — your tests pass.
3. `pnpm exec eslint <your files>` clean.
4. You did not touch a file owned by another agent.
5. Your final report lists: files written, tests written and what they cover, any constant you chose
   yourself and why, and anything in the research that you could not implement as specified.
